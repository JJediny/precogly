{% extends "precogly_auth_base.html" %} {% comment %} Overrides allauth's login page for the OAuth authorization flow. allauth's own template renders through its element/slot system and inherits markup this project does not otherwise use. This renders the same form plainly. Two things carry weight here. `redirect_field` carries the `next` parameter django-oauth-toolkit put on the URL when it redirected here. Without it a user signs in and lands on the site root instead of returning to the consent screen they were part-way through. The heading changes when `next` points at the authorize endpoint. Anyone reaching this page is almost certainly signed in already — the React app is the normal way in, and it holds a JWT rather than a session — so asking for a password looks like the site forgot them. It has not: re-authenticating before an agent is granted standing access to a threat model is the decision recorded in 0007 of the precogly-mcp repository. The copy is what makes that legible, and it is the whole of the mitigation. `next` is read from GET and POST both, because the form posts to the bare login URL and carries `next` as a hidden field, so the query string is gone by the time a failed attempt re-renders this page. {% endcomment %} {% block title %} {% firstof request.GET.next request.POST.next "" as next_url %} {% if "/o/authorize/" in next_url %}Confirm it's you · Precogly{% else %}Sign in · Precogly{% endif %} {% endblock %} {% block heading %} {% comment %} Recomputed rather than shared: a child template renders nothing outside a block, so anything assigned there never exists. {% endcomment %} {% firstof request.GET.next request.POST.next "" as next_url %} {% if "/o/authorize/" in next_url %}
