{% extends "precogly_auth_base.html" %} {% comment %} The consent screen. This is the page that decides whether connecting an agent to Precogly feels like part of the product or like a form someone forgot. Two details are copied from django-oauth-toolkit's default and must stay: the approve button carries `name="allow"`, which is the only thing distinguishing approval from cancellation, and the form's hidden fields carry the client id, redirect URI, scopes and PKCE challenge. Drop either and every authorization fails. `scopes_descriptions` comes from OAUTH2_PROVIDER["SCOPES"] in settings, so the sentences a user reads while deciding are written there rather than here. The shape follows Google's and GitHub's consent screens, because a user arrives here already knowing how this kind of page works and the familiarity is the point. Three things they show that a bare scope list does not: - **which account is granting.** The whole decision is "should this agent act as me", and until it is on screen the user is answering it from memory. - **where they will be returned to.** A consent screen is the last thing standing between a user and a rogue client; the redirect is the only field on it that tells them where they are actually going. - **that access outlives this page.** "You can revoke this later" is a claim, and django-oauth-toolkit routes a page that makes it true, so it is a link. {% endcomment %} {% block title %}Authorize · Precogly{% endblock %} {% block heading %} {% if error %}
