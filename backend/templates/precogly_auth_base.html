{% comment %} Shell for the two server-rendered pages in the OAuth authorization flow. Everything else a user sees is the React application; these two are Django templates because django-oauth-toolkit's authorize view needs a session, and a session cannot be established from a client-side JWT. The classes below are copied out of `frontend/src/components/ui/*.tsx` and `frontend/src/pages/Login.tsx` verbatim, and the stylesheet that resolves them is built from the same tokens the application uses: cd frontend && npm run build:auth-css Copying class strings rather than compiling them by hand is the whole point. The previous version of this file inlined hand-written CSS, and it drifted — into a `prefers-color-scheme` dark mode the application does not have, so a dark-mode machine saw a light product, a dark login page, and a light product again. Decision 0004 in the precogly-mcp repository records why these pages are Django templates at all, and what replaces them when consent has to carry product logic.
